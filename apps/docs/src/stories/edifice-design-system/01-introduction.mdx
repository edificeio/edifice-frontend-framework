# Edifice Design System

Le design system Edifice est un ensemble de **CSS custom properties** générées par `@edifice.io/bootstrap`. Les valeurs viennent de **Figma**, sont recopiées dans des fichiers Sass par un outil de synchronisation, puis compilées en variables CSS.

Changer de thème revient à changer un attribut HTML (`data-product`) : les valeurs changent à l'exécution, sans recompilation.

---

Les composants consomment les couches 1 et 2 via `var(--…)` : ils ne connaissent jamais le nom du thème actif.

## Les thèmes

| Thème | Usage |
| --- | --- |
| `edifice2d` | Nouveau design system, second degré |
| `edifice1d` | Nouveau design system, premier degré |
| `neo` | Portage de l'ancien thème Neo dans le nouveau système (transitoire) |
| `one` | Portage de l'ancien thème One dans le nouveau système (transitoire) |

Tous les thèmes sont déclarés de la même manière : il n'y a pas de différence de nature entre un thème produit et un thème dédié à une plateforme. Voir [Themes](?path=/docs/edifice-design-system-themes--docs).

## De Figma au CSS

1. **Figma** est la source de vérité :
   - fichier **Edifice_UIKit** : les primitives (collections `primitives`, `primitivesLegacy`, `text`) ;
   - fichier **EdificeLibrary_Web** : les variables sémantiques, avec **un mode par thème**.
2. Le plugin Figma **Edifice Token Extractor** exporte ces variables en JSON.
3. L'outil **`tools/figma-sync`** réécrit les fichiers Sass de `packages/bootstrap/src/themes/configs/` à partir de ces exports. Le skill Claude `figma-tokens-sync` le pilote.
4. La compilation de `@edifice.io/bootstrap` génère les variables CSS.

Les fichiers de `configs/` ne se modifient donc pas à la main : on modifie Figma, puis on relance la synchronisation.

---

## Comment le thème est activé

- **Sur toute la page** : `EdificeThemeProvider` (`@edifice.io/react`) pose `data-product` sur `<html>`. La valeur est le dernier segment de `bootstrapVersion` dans le `theme-conf` de la plateforme. Il pose aussi `data-theme` (nom du thème de la plateforme) et `data-skin` (skin choisi par l'utilisateur).
- **Sur une partie de la page** : un thème n'étant qu'un ensemble de variables, poser `data-product` sur un élément applique ce thème à ses seuls descendants. Les `uiOverrides` du `theme-conf` s'en servent, par exemple `'layout.header': { variant: 'v2', theme: '<thème>' }` pour donner au header un thème différent du reste de l'application (voir le hook `useUiOverride`).

## Fichiers source

Tous les chemins sont relatifs à `packages/bootstrap/src/themes/`.

| Rôle | Fichier |
| --- | --- |
| Primitives | `configs/_primitives.scss` |
| Primitives legacy (neo / one) | `configs/_primitives-legacy.scss` |
| Configuration d'un thème | `configs/_<thème>.scss` |
| Couleurs des icônes d'applications | `configs/_icons.scss` |
| Breakpoints et mixins de media queries | `configs/_breakpoints.scss` |
| Génération des variables (mixins) | `_theme-api.scss` |
| Déclaration d'un thème et ses overrides | `<thème>/_index.scss`, `<thème>/overrides/` |
| Fonds de page | `_backgrounds.scss` |
| Point d'entrée | `_index.scss` |
